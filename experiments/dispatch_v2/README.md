# V2：母车与无人机协同调度强化学习实验

基于 `frontend-showcase-20261014` 的 `b7a58b04dafda904f5fa57f201ba1b088a8034eb`，工作分支为 `frontend-showcase-20261014V2`。

训练/评估脚本是独立实验；最终策略已通过 ONNX 接入 V2 的动态订单前端，见 [接入说明](../../frontend/docs/v2-integration.md)。本目录的性能数字仍仅对应静态订单离线环境，未针对动态到单重新训练。原有四个 ONNX 模型保留作历史对照。
最终数据、结论、学习曲线见 [REPORT.md](REPORT.md)；可直接加载的模型为 `results/dispatch_policy.pt`。

## 学习内容与动作改变

改用集中式、协作式、带动作掩码的 PPO，学习离散调度动作，而非继续训练连续飞行方向。
这是一个共享策略网络依次输出四个设备的协作决策，不是四个互相独立的策略。

每个任务波次：

1. 策略为母车选择 9 个中央道路接应点之一；这些点组成 3×3 网格，坐标为 `{-30,0,30}²` 米。
2. 策略为 UAV 1、2、3 依次选择不同的待取订单，最后一个波次不足三单时只派出需要的设备。
3. 进行必要的预起飞补能，然后无人机共同出发、母车同时驶向接应点。
4. 按解析行程模型推进飞行、悬停取件、等待母车到达、单舱排队卸货；全部回收后进入下一波。

所有订单位置、状态和三架无人机的电量、速度、能耗系数、母车当前位置及拟定接应点都进入观察。
订单通过共享编码器及均值/最大池化构成集合表示，候选动作共享评分网络，支持 9–18 单、不同排列。
已选订单被动作掩码排除，策略无法重复预约；电量不足自动补足保留电量后才出发。

网络不是直接套原 MADDPG 权重，而是从头训练。最终两个候选均没有行为克隆或规则示范预热。
探索阶段试过规则预热和较低能耗权重，原始记录保留在 `runs/`，不作为最终结论的依据。

## 优化目标

每单在时刻 0 产生，以货物在母车完成卸货的时刻作为完成时间。

```text
J = 平均订单完成时延（秒） + 6 × 每完成一单的无人机能耗（Wh）
reward = -(本波次所有未完成订单的等待时间积分 / 本轮订单数
           + 6 × 本波次无人机能耗 / 本轮订单数) / 100
```

累计奖励严格等于 `-J/100`，有自动测试验证。PPO 的折扣系数为 1，GAE lambda 为 0.95。
权重 6 的单位是秒/Wh，表示本轮选择的时延与能耗折中，不表示同时求得两个目标的全局最小值。
剩余订单等待也计入损失，因此不会通过只完成容易订单来美化平均时延。

## 仿真范围与假设

- 全部订单提前已知，数量为 9/12/15/18；位置由随机簇生成，水平范围约 ±95m，高度为 0/8/16/24m。
- 三机速度随机为 7–9m/s，垂直速度 2m/s；母车按曼哈顿道路距离、4m/s 移动。
- 电池 45Wh，保留 4.5Wh，初始电量随机为 16–45Wh，补能速率 0.35Wh/s。
- 耗电由水平距离、垂直距离和悬停等待计算；取件 4 秒，单舱卸货 2 秒。
- 预起飞充电期间母车保持静止。所有本波次设备准备好后共同出发；不能让车先走、飞机留在原坐标充电。
- 订单完成率由有限任务及合法动作机制保障。100% 完成不能解释为策略学会了真实世界安全控制。
- 能耗系数是研究用假设，没有真实机型标定；Wh 数值及秒数不能作为实机性能承诺。
- 不包含动态订单到达、避障、风、通信故障、载荷差异、车轮动力学或充电器功率分配。
- 分波次共同出发/回收缩小了调度空间，尚不支持异步连续派单和途中重派。前端接入前需要另做适配。

## 数据隔离与停止判据

训练场景种子 `[0,999999]`，验证集为 `[1000000,1000063]`。
每 5 次 PPO 更新在固定验证集评估一次，只用验证目标选择检查点。

探索集为 `[2000000,2000255]`；第一版额外检查用过 `[3000000,3000511]`。
发现预起飞充电时序问题后修正环境并重新训练，最终测试改用此前未使用的 `[4000000,4000511]`。
最终模型在查看这批测试结果前，已通过验证集冻结，见 `results/selection.json`。

本轮停止条件：

- 两个随机训练种子的验证曲线进入平台，最后 60 次迭代的最佳值改善低于 1%。
- 相对较强的时间/能耗规则，最终测试的平均时延与总能耗同时下降；配对 bootstrap 95% 差值区间均低于零。
- 综合目标改善至少 1%，所有任务完成，环境约束测试通过。

这是有限实验中的经验收敛和基线改进，不是全局最优证明。
两次训练用于初步稳定性检查，仍不足以取代大规模多种子研究。

## 基线与消融

所有方法使用完全相同的订单、电池、速度、能耗参数和执行环境：

- `nearest_fixed`：母车停在中心，无人机依次选择离母车最近的订单。
- `nearest_centroid`：母车选择最接近剩余订单中心的接应点，无人机选最近订单。
- `cost_centroid`：母车仍跟随订单中心，无人机选择预计回收时间加 `6×飞行能耗` 最小的订单。
- `ppo`：母车接应点和无人机订单都由学习策略选择。
- `rule_mother`：仅将母车替换为中心规则，保留学习选单。
- `rule_orders`：仅将无人机选单替换为时间/能耗规则，保留学习母车。

消融是固定已训练策略后的动作替换，不是分别重新训练的独立最优策略，存在状态分布变化。
配对置信区间以相同场景种子配对，进行 5000 次 bootstrap。

## 复现

在仓库根目录执行；实验使用当前机器的 CPU，不需要浏览器、Broker 或前端依赖。

```powershell
python -m pip install -r experiments/dispatch_v2/requirements.txt
python -m unittest discover -s experiments/dispatch_v2 -p test_*.py -v

python experiments/dispatch_v2/train.py --iterations 240 --episodes 96 --seed 7 --warm-episodes 0 --warm-epochs 0 --energy-weight 6 --output experiments/dispatch_v2/runs/ppo_wave_sync_seed7
python experiments/dispatch_v2/train.py --iterations 240 --episodes 96 --seed 42 --warm-episodes 0 --warm-epochs 0 --energy-weight 6 --output experiments/dispatch_v2/runs/ppo_wave_sync_seed42

python experiments/dispatch_v2/evaluate.py --runs experiments/dispatch_v2/runs/ppo_wave_sync_seed7 experiments/dispatch_v2/runs/ppo_wave_sync_seed42 --test-start 4000000 --test-count 512
python experiments/dispatch_v2/infer.py --seed 5000000
```

每个正式训练运行 240 次更新、每次 96 个完整任务，共 23040 个训练任务。
运行中会记录实际训练目标、固定验证集表现、熵、近似 KL、损失、运行时间，并保存最佳和最后检查点。
模型选取依据验证集，最终曲线显示所有验证点，不只显示历史最低点。

`runs/ppo_v1` 使用早期未加入能耗权重观察特征的环境；`runs/ppo_energy6`、
`runs/ppo_scratch_seed7` 使用修正充电时序前的环境，其快照是 `archive/env_schema2.py`。
这些旧检查点不应由当前 `infer.py` 加载，也不应与最终环境结果混报。

## 文件

| 文件 | 用途 |
|---|---|
| `env.py` | 场景生成、波次调度、电量、时延与能耗计算 |
| `model.py` | 全订单集合编码、候选动作评分、价值网络 |
| `train.py` | 可选规则预热、PPO、验证选模、探索评估 |
| `evaluate.py` | 冻结选模、最终新场景测试、消融、区间和图表 |
| `infer.py` | 加载最终模型，对一个新场景生成调度任务 |
| `test_env.py` | 奖励一致性、电池余量、队列、时序、掩码与排列等变测试 |
| `results/dispatch_policy.pt` | 最终可加载策略及权重/结构元数据 |
| `results/summary.json` | 最终指标、置信区间和平台判据 |
| `results/example_mission.json` | 一轮完整任务的接应点、选单和回收时序 |

> 本文为改造前评估。之后用户指定 RTX 3060，并改为圆润动画风格；优化已实施，最新资产预算与实测边界见 [RTX 3060 优化记录](rtx3060-optimization-20261014.md)。下文高负载和硬件选型不代表当前版本。

按用户要求暂停收尾与改造。本次核算模型拓扑、实例数量、运行资源以及本机硬件；没有继续改变场景、算法或画质设置。

树木与灌木合计 72,617,468 面，占 **91.26%**。主建筑不是最大的负担：七栋楼约 420 万面，景观约 7262 万面。原始高密度扫描树直接大规模实例化，是本版资源选择和实时渲染预算不匹配的问题。后续增加周边 24 棵树又增加了 25,733,112 面；此前约 5384 万面也已经过重。

InstancedMesh 已共享景观几何与材质，避免每棵树重新上传全部资源并减少绘制调用，但它不会省去各实例的顶点/三角形处理。当前同一种树所有实例在同一组内，没有距离 LOD、分区实例裁剪或遮挡剔除；看到部分树时仍可能提交整组。

运行所引用的唯一资源 48 个文件，共 **509,140,417 B / 485.55 MiB**，包括模型、贴图与 HDRI，不乘实例数。此值不是 GPU 显存占用：贴图上传后通常展开，GPU/CPU 有额外缓存；反过来，几何实例也不会每棵都复制一整份二进制。

## 已有绘制观测及限制

上一轮浏览器真实绘制诊断出现过 **2327 draw calls、238,784,323 个含阴影及多次绘制的三角面/帧**。这个数不是额外加载了 2.39 亿个不同面，而是同一模型在不同绘制通道反复处理。帧时短窗约 1–2s，自动化浏览器调度与其它负载没有隔离，不能据此生成不同显卡的 FPS 对照表。

当前已存在暂停阴影缓存；它降低静止画面的重复阴影处理。任务运行时仍更新整张 4096 阴影贴图。另有玻璃双面透明、树叶 alpha 遮罩、多材质、DPR 上限 1.75 和持续的前端状态刷新开销。DPR 1.75 的像素数为 DPR 1 的 3.0625 倍；这是配置上限，不代表本次浏览器始终使用该倍率。

新本轮未重新加载沉重地图进行独占 GPU 基准，当前 Chrome 没有可读取的既有地图标签页。因此采用准确的模型核算与上一轮真实观测，不能把不同口径混成一次新的同屏性能实测。

## 本机与配置建议

系统读取：**Intel Core i5-14500，14 核/20 线程，约 31.6GiB 内存，安装的显卡仅查到 Intel UHD Graphics 770 核显**。Win32 的 AdapterRAM 字段不能作为核显可用显存上限；本机是否发生软件渲染，尚未通过 Chrome GPU 诊断确认。

结合八千万面规模和核显配置，GPU 承载压力是明确的重点怀疑；没有通过 GPU 时间查询或 CPU 火焰图完成瓶颈占比测量。既有四个 ONNX 推理批次只需约亚毫秒，且每 0.5s 推理，不支持将地图卡顿归因于后端神经网络。CPU 与内存可以先保留，优先处理模型预算和独立显卡。

推荐以**优化后场景**采购/验收：

- 1080P/2K 演示：桌面 RTX 5070 Ti 16GB，现有 i5-14500 或同级现代 CPU，32GB 内存，NVMe SSD；开发、录屏与多程序同时运行可用 64GB。
- 更高画质/4K 余量：桌面 RTX 5080 16GB，现代高单核性能 CPU，64GB 内存，NVMe SSD。
- 保持当前原始负载：即使 RTX 5090 32GB 等高端独显也不能未经测试保证稳定 60FPS；不建议为当前不合理的资源预算直接采购最高端电脑。

这些是工程选型建议，**不是本项目在相应显卡上的实测 FPS**；同名笔记本 GPU 与桌面 GPU 不应视为同一配置。应在目标机以具体视角、1080P/2K/4K、运行中/静止状态测试，并确认 Chrome 硬件加速。

建议先以主视角 **200～500 万个独立三角面、约 300～500 次绘制调用**作为优化后的工程预算起点，再依实际效果和测量调整，并非 WebGL 的硬上限。保持获选外观，通过树木/灌木/无人机 LOD、近景高精度、远景烘焙法线、分区裁剪、建筑室内细节裁剪、静态与动态阴影分开等办法减负，不需要用低质量几何占位替换建筑。

## 后端规则变动与边界

前端继续只处理遥测插值、渲染和交互，不运行 ONNX 或自行完成订单。四个 ONNX 模型、观察向量、原始目标点、初始位置、水平/垂直速度设定和业务统计保留。

原到达规则继续为水平误差≤0.35m、高差≤0.2m、速度≤0.15m/s，并连续悬停 0.8s；取件动画 3s，卸货 1.5s。没有提前把“已装载”算作“已回收”。

为匹配原创单接货舱，Python 增加权威 FIFO 接货队列与舱盖进度：母车接货期间停车；只有接货所有者可卸货，其他两架飞机前往独立等待位置。交货后先用 0.65s 收回吊具，再离舱落到分离的停机位；离舱超过 2m 才释放接货位。地面待命再出发先垂直爬升，避免从地面瞬移到巡航高度。最后一个包裹回收后，等三机归位和舱盖关闭才结束任务；暂停和重置也覆盖这些阶段。

这是仿真调度和视觉机构适配；母车仍执行原模型在服务区内的运动，不是沿环路的交通路径规划或完整车辆动力学。没有实现动态云边卸载，也没有把 AI“已配置”显示成真实通信成功。Gemini 配置沿用既有私有环境，未新增在线调用或公开密钥。

最终新开页面检查发现旧 MQTT 连接的 retained 离线通知可能覆盖新服务的在线状态。已增加后端每秒一次的真实状态心跳，并保留离线遗嘱和前端遥测过期冻结；新连接持续心跳测试通过，页面重新确认“后端已连接”。

## 性能与后续发布限制

按用户要求保留高密度模型。Jacaranda 原始几何文件约 208MB，单棵约 386 万三角形；当前树冠遮罩需启用抗锯齿和较低 alpha 阈值，否则远景叶片会因 mip 采样消失。此版没有做几何减面。

当前自动化浏览器短窗出现约 1–2FPS、P95 约 1–2s；暂停阴影缓存启用前的某窗口记录 2327 calls、238,784,323 个含阴影/多次绘制的三角形。单栋预览也出现接近 1s 的帧间隔。浏览器窗口调度和同机负载未隔离，不能据此确定瓶颈，更不能宣称流畅度合格。新电脑上需要重新做前台独占 GPU 测量；渲染高品质完成不等于性能验收完成。

Jacaranda `.bin` 超过 GitHub 单文件 100MB 限制。后续上传必须使用 Git LFS 或独立资产托管；这轮完成本地运行与验收，未推送这些新改造和大模型。独立静态预览采用按需渲染，漫游时持续渲染。暂停时固定日光阴影缓存复用，运行及重置时重新绘制；模型几何与阴影分辨率不变。

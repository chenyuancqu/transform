## 包裹取件判定与动画（2026-10-13，当前业务版本）

原 `checkOrderCompletion` 的 0.08 是归一化距离：其到达区域水平半径约 16m、高度半径约 4m，且 R3F 无人机又额外抬高 2.45m，导致画面与判定都提前。本轮将共享米制单位放入 `MissionRules.js`，显示机体中心与业务位置一致，删除 2.45m 显示偏移。

新流程是：独占分配包裹 → ONNX 巡航 → 18m 内减速精确对准 → 稳定悬停 → 吊具下降、夹取、提升、确认 → 携包返航 → 母车入舱 → 接下一单。保留当前工作区的母车 0.0075、无人机 0.015 巡航系数与 0.003 电量消耗设置；原模型若给出绕飞或停滞动作，则使用目标引导兜底，不放宽到达门槛。

| 项目 | 当前规则 |
| --- | --- |
| 包裹中心 | 地面取件托盘上方，世界 Y=0.6m；保留原水平坐标，替换原先 5–11m 的悬空目标高度 |
| 取件悬停位 | 无人机中心在包裹中心正上方 0.95m |
| 到位条件 | 水平误差 ≤0.35m，高度误差 ≤0.20m；业务位置与渲染位置均满足 |
| 悬停速度 | 实际显示机体速度 ≤0.15m/s，防止快速飞过目标被算到位 |
| 稳定时长 | 连续满足至少 0.8 仿真秒，离开容差区域则清零重来 |
| 装载 | 3 仿真秒：先放下吊具，再提起包裹，最后绿环确认；动画与仿真时间都结束才计入取件 |
| 返航与入舱 | 每架无人机有独立停靠位；进入母车 6m 停靠区后母车驻停，入舱动画 1.5 仿真秒 |
| 统计含义 | `completedOrders` 为已取件，`deliveredOrders` 为母车已回收；全部回收后自动暂停 |

动画随速度滑块缩放。暂停冻结机体移动、吊具、包裹和装载进度；旋翼与地面提示光圈仍保留展示动画。重置丢弃旧仿真实例，避免异步推理把已重置数据写回。取走包裹后托盘保留，原地包裹及编号消失；包裹挂在无人机下方返航，入舱结束后解除携带。新增 `uavDistanceMeters`，按水平 200m / 高度 50m 分别转换后累计，R3F 航程不再直接乘旧的 100 系数。
